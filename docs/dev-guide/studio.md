# Studio 原型 v3 设计

一句话：v2 的屏幕上只有一堆任务卡片，看不到真正在改的东西；v3 把「正在编写的客户项目方案」放上屏幕正中间，任务、验收、版本全部围绕这份文件转。

## 现在的问题

打开 v2，你看到六张任务卡片。但用户心里想的是：方案改到哪了？报价定了没有？屏幕上没有答案。任务卡上写着「报价核算 · 待验收」，可要验收的内容只有一行文字。这就像让你审批一份文件，但只给你看文件名。

## 打开 v3 你会看到什么

拿一个真实业务当例子——量潮数据接了一个高校的数据治理项目，方案要几个人几朵云一起写。按一次完整的使用过程讲：

1. 左边大半屏是《A 校数据治理项目方案》正文，分成「背景与目标 / 数据范围 / 处理流程 / 报价 / 交付计划」几节，右上角标着当前版本 v1。右边窄栏是任务列表。
2. 右栏第一条：「数据可行性评估 · 数据云执行中」。几秒后它完成——左边「处理流程」一节出现修改对照：红字删除线是原文，绿字是数据云提议的新文字（比如把「按月清洗」改成「按周清洗」，附理由：客户数据源每周更新）。
3. 你读完修改，觉得合理，点「通过」。绿字并入正文，版本号跳成 v2，方案下方多一行记录：「v2 · 数据可行性评估 · 数据云」。
4. 右栏刷新：「报价核算（执行云）」从灰变亮，可以开工。
5. 把最后的任务也验收完，页面顶部出现一行字：方案定稿，全部任务验收通过。

## 验收的两种结果

- **通过**：修改进正文，版本号加一。
- **驳回**：必须写一条意见（比如「交付周期写死 30 天太激进，客户数据源每月才更新」），任务退回给干活的那朵云去改，草案一个字不动。

## 右侧任务栏

从上到下只有三段，一眼扫完：

- **等你拍板**（黄色）：有修改等你判定。点任务，左边方案跳到对应章节。
- **正在干**（蓝色）：哪朵云在干哪件事，干完自动交修改。
- **可以开始**（灰色，就绪后变亮）：上游的活都验收完了，随时开工。

## 派活：说话就行

顶部一句话输入框。demo 预置了几个听得懂的意图（比如「增加客户确认环节」），听到就拆成任务；听不懂就直说「这句我还不会拆」，不会偷偷塞一个假任务。

## 哪些是真的，哪些是演的

- **真**：方案正文、修改内容、版本记录。验收通过后方案真的变了，刷新也不丢。
- **演**：「云在干活」是预排的——每朵云交回什么修改，事先写好在数据里；延迟几秒只是为了有「在干活」的感觉。
- **没做**：真的 AI 拆解、真的云接入、多人协作。

## 给实现者

- 新增两个类型：`Document`（title、sections、version，就是那份方案）和 `Change`（sectionId、before、after，就是一条修改）。任务新增 `output: Change[]`——任务干完，交回来的就是一条修改。
- 沿用 v2 的工具链（React + Vite）和 localStorage 存储，key 换 v3。
- 评判原则见仓库根 `AGENTS.md`；v2 的问题记录见 `examples/studio/README.md`。

## 做完怎么算合格

1. 不看任何说明，打开 5 秒内知道现在该自己干什么。
2. 每次验收都看着章节的修改对照拍板，不是看一行摘要。
3. 驳回之后，方案一个字都没变。
4. 遮住右边任务栏，左边仍是一份能独立读的方案。
5. 按 AGENTS.md 自评分，目标 5 分以上。
