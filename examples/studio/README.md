# qtcloud-studio-demo

量潮云工作台（CoWork 形态）交互原型 v2，React 19 + TypeScript + Vite。

## 这个屏幕要回答的问题

**用户面对工作台，能不能不看任何文档就明白现在该他干什么？**

由此确定的层级（自上而下）：

1. **派活指令条**：说要什么，系统拆解（demo 为模拟拆解，真实实现由协作目录 + LLM 承担）
2. **等你拍板**：待验收任务是全屏最高视觉优先级——验收是用户唯一的法定职责；驳回必须附意见并回传执行者
3. **现在可动**：就绪任务（上游全部验收通过）与进行中任务。就绪判定让 DAG 第一次有了调度语义
4. **全景 DAG**：退居折叠层，只作总览
5. **反馈**：验收、驳回、派活均有可感知回应（toast、高亮、完成横幅）；数据存 localStorage，刷新不丢

上一版（v1）的教训：界面是数据结构的投影，六张卡片平铺、状态靠读标签、按钮藏在小字里——屏幕没有立场。设计决定先于组件存在。

## 运行

```bash
npm install
npm run dev
```

「重置」按钮恢复初始案例（招聘政策修订，见 `src/data.ts`）。

## 边界与假设（未解决的）

- 拆解为模拟：一句话派活后仅创建单任务，执行者默认「用户」——自动指派与多步拆解未实现
- 单机单人：无协作、无权限、无账号；空间只有硬编码的一个
- 交付物仍是文本，未引用文件或结构化数据
- 概念契约见 `src/types.ts`（v2 新增 `review` 字段：驳回意见属于完成判定的一部分）

正式客户端规划见 `../../src/studio/ROADMAP.md`。
